Plan de pruebas

Plan de pruebas para una API REST

El objetivo del plan de pruebas es validar que la API cumpla con los requisitos de negocio, responda con los códigos HTTP esperados y maneje errores, autenticación, seguridad básica y datos válidos en todos sus endpoints.

Proyecto

API de gestión de usuarios

Ambiente

QA / Staging

Versión

v1.2.0

Responsable

Equipo QA

1. Introducción

La API REST permite gestionar usuarios, autenticación, consultas y operaciones básicas CRUD. El objetivo principal del plan es asegurar que los endpoints funcionen correctamente, validen entradas, entreguen respuestas consistentes y cumplan con los requisitos del negocio.

2. Alcance

  • • Autenticación con login y token.
  • • Consulta, creación y actualización de usuarios.
  • • Validación de permisos y roles.
  • • Manejo de errores HTTP y mensajes de respuesta.
  • • Verificación de datos inválidos, nulos y límites de entrada.

3. Fuera de alcance

  • • Pruebas de rendimiento, estrés y carga.
  • • Pruebas de seguridad avanzadas como pentesting.
  • • Validaciones de terceros o integraciones externas no definidas en el sprint.

4. Estrategia de pruebas

Tipo de prueba

Pruebas funcionales y de API basadas en historias de usuario, validación de datos y escenarios de error.

Método

Ejecución manual con Postman y validación de respuestas HTTP, payloads y códigos de estado.

Ambiente

URL base de pruebas: https://api-qa.example.com

Datos de prueba

Usuarios válidos, usuarios inexistentes, credenciales incorrectas, campos obligatorios y payloads inválidos.

5. Riesgos y mitigación

Riesgo Probabilidad Impacto Mitigación
Ambiente de pruebas no disponible Media Alto Validar disponibilidad del servicio antes de la ejecución y preparar un entorno alternativo.
Datos inconsistentes en QA Baja Medio Preparar datos de prueba estandarizados y limpiarlos antes de cada ejecución.
